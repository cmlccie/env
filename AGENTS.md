# AGENTS.md

Instructions for AI coding agents working in this repository.
`.claude/CLAUDE.md` is a symlink to this file — edit this one.

## What this repo is

Personal dotfiles for macOS, Linux, and WSL2. `home/` mirrors `~`: every file under it is
symlinked into the user's home directory by `setup-home.py`, so **editing `home/<path>`
edits the live `~/<path>`** — there is no build or deploy step for existing files. Adding a
*new* file under `home/` does require re-running `setup-home.py` to create its symlink.
A symlink inside `home/` is skipped by `setup-home.py` and will never be deployed.

`platforms/` is *not* linked by `setup-home.py`; it holds per-OS extras (Brewfile, app
preference exports, a Raspberry Pi `.bashrc`) applied by hand.

## Commands

```sh
./setup-home.py                    # symlink everything under home/ into ~ (real files
                                   #   are backed up as *.backup.<iso-timestamp>)
./setup-home.py ~/some/file        # adopt an existing ~ file INTO home/, leaving a symlink

./upgrade-packages.sh              # all: nix, brew, python, conda, node, rust, completions
./upgrade-packages.sh nix brew     # or any subset of those subcommands

home/.local/bin/update-shell.sh    # idempotent per-machine migration; run after pulling
home/.local/bin/sandcat-sync DIR   # sync a sandcat project's agent container with this repo

brew bundle --file platforms/macos/Brewfile
brew bundle cleanup --file platforms/macos/Brewfile --dry-run   # ALWAYS dry-run first
```

## Verifying changes

There is no test suite. The checks that matter for shell config:

```sh
# Every shell startup path must be COMPLETELY silent. Non-zero byte counts break
# scp, rsync, and git-over-ssh.
for s in 'zsh -c' 'zsh -lc' 'bash -c' 'bash -lc'; do printf '%s: ' "$s"; eval "$s true" 2>&1 | wc -c; done

shellcheck home/.config/shell/*.sh home/.bashrc home/.bash_profile   # brew install shellcheck
bash -n upgrade-packages.sh                                          # after editing scripts

bash -lc 'echo $PATH' | tr : '\n' | sort | uniq -d   # expect no duplicates
```

`update-shell.sh`'s `verify()` step runs the silence and PATH-duplicate checks; running it
is the closest thing to a test run.

## Shell startup architecture

```text
.zshenv / .zprofile / .bash_profile / .bashrc / .profile / $BASH_ENV
        └── env.sh ──┬── lib.sh      (helpers; ABOVE the __SHELL_ENV guard)
                     └── paths.sh    (PATH;    BELOW the guard)

.zshrc / .bashrc
        └── interactive.sh ── aliases.sh
```

All shared config lives in `home/.config/shell/`. The README's "Shell Startup" section is
the full reference; the constraints most likely to bite an edit:

- **`env.sh` must stay silent, POSIX, and side-effect free.** It is exported as `$BASH_ENV`,
  so every non-interactive `bash` on the machine reads it. No aliases (zsh expands aliases
  non-interactively, silently shadowing binaries agents invoke), no `eval "$(tool hook)"`,
  no prompts, no disk writes, nothing that prints.
- **`lib.sh` above the `__SHELL_ENV` guard, `paths.sh` below it.** Environment variables
  survive `fork+exec`; shell functions do not. A nested shell must redefine helpers but
  should inherit `PATH` rather than rebuild it.
- **Login files `unset __SHELL_ENV` first.** macOS `path_helper` runs between `.zshenv` and
  `.zprofile` and hoists `/usr/bin` ahead of Homebrew; clearing the guard re-applies the
  correct order.
- **`lib.sh`, `paths.sh`, `env.sh`, and `.profile` may be read by `dash`** — no bashisms,
  no arrays.
- **A variable that locates a bin directory** (`HOMEBREW_PREFIX`, `GOPATH`, `CARGO_HOME`,
  `NVM_DIR`) goes in `paths.sh` beside the `path_prepend` that uses it.
- **The devbox global profile goes on `PATH` via a static `path_prepend` in `paths.sh`** --
  never `eval "$(devbox global shellenv)"`. Same reasoning as the Homebrew block above it:
  `env.sh` is `$BASH_ENV`, so a fork-per-shell hook there is both slow and a silence
  violation. Do not add `/nix/var/nix/profiles/default/bin`; devbox self-locates it.
- **Portability helpers from `lib.sh`:** `have`, `source_if`, `path_prepend`, `path_append`.
  Guard every tool reference with `have` and every path with these — no absolute paths, no
  assuming a tool is installed. This repo targets macOS, Linux, and WSL2 from one checkout.

Deliberate choices that read like bugs — do not "fix" them:

- `GIT_EDITOR=false` in `env.sh` so an agent that forgets `-m` gets a loud error instead of
  a silent empty commit; `interactive.sh` overrides it with a real editor for humans.
- No `PS1` in `.bashrc`. Interactive bash exists here for AI agents, which parse output;
  `~/.local/bin/simple-prompt.sh` is sourced on demand for a human prompt.
- Completions are generated by `./upgrade-packages.sh completions` into
  `~/.oh-my-zsh/completions`, never at shell startup.
- Homebrew still owns exactly three formulae. `tetra` (nixpkgs `tetragon` is
  `platforms.linux` and builds from source), `pinentry-mac` (macOS GUI prompt), and
  `chipmk/tap/docker-mac-net-connect`. That is not drift -- do not migrate them to Nix.
- `nvm`, `oh-my-zsh`, and `powerlevel10k` are deliberately unmanaged. `nvm` is not in
  nixpkgs in a usable form; the other two need writable trees the Nix store cannot provide.
- `update-shell.sh` runs `chsh -s /bin/zsh`. A devbox generations symlink under
  `~/.local/share` must never be a login shell.

## Package management

Three manifests, no overlap. Adding a tool to the wrong one is the mistake to avoid.

| Manifest                   | Manager         | Owns                                    |
| -------------------------- | --------------- | --------------------------------------- |
| `nix/packages.json`        | `devbox global` | command-line tools, host and agent      |
| `platforms/macos/Brewfile` | Homebrew        | macOS GUI apps, fonts, and 3 formulae   |
| `python/uv-tools.txt`      | `uv`            | Python command-line tools               |

- **`nix/packages.json` is the only file to edit** for a CLI tool. `shared` goes to both the
  host profile and the agent container; `host_only` goes to the host alone. `nix/global.json`
  is generated from it -- never edit that.
- **Do not run `devbox global add` or `devbox global rm`.** `./upgrade-packages.sh nix`
  applies the manifest with `devbox global pull --force`, which is authoritative in both
  directions. `add` only ever adds, so using it makes the manifest and the profile diverge.
- **Nix supplies only `uv` from the Python toolchain.** `ruff`, `mypy`, `ipython`, and
  `poetry` are `uv tool` installs declared in `python/uv-tools.txt`. Never move them into
  `nix/packages.json`.
- **Pin versions when a set stabilizes.** `devbox.tools.json` has no nixpkgs revision key, so
  `name@version` is the only lock-step mechanism between host and container; `@latest`
  resolves independently on each side.
- **`sandcat-sync <project>`** regenerates a project's `.devcontainer/devbox.tools.json`,
  seeds `.sandcat/settings.json`, and re-inserts the dotfiles block into `Dockerfile.app`.
  Re-run it after every `sandcat init`, which regenerates that Dockerfile.

## Python

`uv` owns everything Python. There is no system-wide Python environment, no `pyenv`, and no
Poetry-managed system packages — that arrangement was retired.

`python/uv-tools.txt` is the manifest of command-line tools. Each non-comment line is passed
verbatim to `uv tool install`, so extras and plugins are declared inline
(`poetry --with poetry-plugin-export`). `./upgrade-packages.sh python` installs anything
missing, then runs `uv tool upgrade --all` and `uv python upgrade`. Binaries land in
`~/.local/bin`, already prepended by `paths.sh`.

- **Libraries never go in `uv-tools.txt`** — only CLI tools. Every project gets its own
  `uv`-managed virtual environment.
- **Poetry is deliberately retained** as one of those tools, so Python projects that predate
  the move to `uv` stay maintainable. It has no role in this repo's own package management.
  Do not propose removing it.
- Do not reintroduce `pyenv`, a global `pip install`, or a repo-level Python project.

## Keeping documentation in sync

Three files, one source of truth for agents:

| File               | Audience | Notes                                    |
| ------------------ | -------- | ---------------------------------------- |
| `README.md`        | human    | the full reference; rationale lives here |
| `AGENTS.md`        | agents   | this file; operational rules only        |
| `.claude/CLAUDE.md`| Claude   | **symlink to `AGENTS.md`** — never a file |

- A change to `upgrade-packages.sh`, `setup-home.py`, `python/uv-tools.txt`,
  `nix/packages.json`, `sandcat/settings.json`, the Brewfile, or the shell load graph
  updates **both** `README.md` and this file in the same change.
- Never replace `.claude/CLAUDE.md` with a regular file, and never add a root `CLAUDE.md` —
  either one would double-load alongside this file.
- `home/.config/agents/AGENTS.md` shares this filename but is the user's **global** agent
  instruction file, deployed to `~/.config/agents/AGENTS.md` and in force on every project.
  Same for `home/.claude/settings.json` and `home/.claude/CLAUDE.md`. Changing those affects
  the whole machine, not this repo — say so explicitly before editing them.
